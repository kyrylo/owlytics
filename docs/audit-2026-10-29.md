# Correctness audit — 29 October 2026

Scope: one audit pass of collection, reporting, imports, date controls, filters,
realtime, and responsive dashboard interactions. Reference: Plausible's public
documentation retrieved on this date. This is a behavioral comparison, not a
claim of complete compatibility with every Plausible edition.

## Verified fixes

1. **Cross-midnight engagement headlines.** Two views of the same page in one
   visit, on opposite sides of midnight, with 1s/20% and 2s/80% measurements
   produced a 1.5s headline and 50% depth. The weekly chart correctly showed
   3s/80%. Headlines now aggregate measured page visits across the selected
   range before averaging. Daily buckets retain their own denominators. The
   same fix covers comparison queries and CSV summaries, including when the
   page table is not requested. Aggregation still uses bounded caches and
   SQLite spill tables; no additional event scan or schema migration is needed.
2. **Lost final foreground time.** After a 1s visit, blur, and another 1s visit,
   leaving the page previously discarded the buffered second. Pagehide,
   visibility becoming hidden (the last reliable mobile lifecycle signal),
   and SPA navigation now flush the cumulative measurement, even below the
   three-second buffering threshold. Identical final snapshots remain silent;
   retry IDs, privacy checks, and server-side deduplication are unchanged. The
   browser regression uses a non-bot User-Agent and verifies receipt in SQLite,
   since Chrome can omit request events from an unloaded renderer.
3. **Mobile report spacing.** Short tables inherited a 390px minimum card
   height, leaving large gaps between reports. At widths up to 700px, cards
   now fit their content. Desktop sizing, map sizing, palette, typography,
   chart controls, and branding are unchanged.

The first two defects were reproduced with failing regression assertions before
the fixes. Historical engagement already received by the server is corrected by
the report change. Foreground time never transmitted by an older tracker cannot
be recovered.

## Intentional differences and constraints

- Rust server, SQLite-only persistent and spill storage, one owner, no analytics
  cookies or browser storage. Owner dashboard preferences may use localStorage;
  owner authentication uses cookies. These are separate from public tracking.
- DNT/GPC and automated-browser signals suppress collection. Bot recognition is
  a local User-Agent heuristic, not Plausible's broader maintained spam service.
- The dashboard works without JavaScript; live refresh and interactive tooltips
  are progressive enhancements. Normal date reports do not periodically refresh.
- Import is a CLI operation requiring a visitors file and disjoint import date
  ranges. Custom events/properties are explicitly reported as ignored. Retained
  source/UTM export relationships can support combined acquisition filters.
  No identities are synthesized to deduplicate historical aggregates.
- Dashboard ZIPs are snapshots: 100 rows per page report and 300 per other
  breakdown, with limits stated inside the archive. They are not full Plausible
  migration exports. SQLite backups preserve complete stored data.
- Light/dark appearance follows the system. There is no separate theme picker.

## Remaining issues and verification limits

- Visitor hashes remain an approximation: shared IP/User-Agent combinations
  can merge people, and changes can split them. Imported visitor totals cannot
  be deduplicated across independent aggregates. These are model limitations.
- Browser validation in this pass uses desktop Chrome, including touch/mobile
  emulation and JavaScript-disabled contexts. Firefox, Safari/WebKit, real
  mobile hardware, and production-scale workloads are not certified by it.
- Database regression tests use disposable local fixtures. Container rollout
  and production health/asset verification are reported separately from those
  application and browser checks.

## Worthwhile feature gaps

1. Safe timezone editing with native aggregate rebuilding and an explicit policy
   for historical imports whose original timestamps are unavailable.
2. Saved filter segments, using the existing filter representation.
3. Full streaming migration exports and import review/removal controls, separate
   from the bounded dashboard snapshot.
4. Optional goals/custom events, then outbound links and downloads, with clear
   interactive/non-interactive bounce semantics and a small tracker footprint.
5. Broader browser coverage and maintainable bot/source classification fixtures.

## Follow-up dashboard pass

Reference: the [live Plausible dashboard](https://plausible.io/plausible.io),
[comparison controls](https://plausible.io/docs/compare-stats), and
[filter documentation](https://plausible.io/docs/filters-segments), inspected on
2026-10-29. Accessibility-specific changes were excluded at the owner's request.

### Verified fixes and workflow changes

- Comparison headlines now show both periods' totals and date labels. The old
  render had zero previous-total elements; the regression requires all six.
  Missing imported session metrics remain unavailable, rather than becoming zero.
  Comparisons disabled and realtime views do not show invented prior values.
- Expanded reports open over the dashboard, with a bounded table, sticky column
  headers, sorting, pagination, and a search field beside the title. Search is
  debounced and preserves typing; ordinary GET forms remain usable without JS.
  Close, backdrop, and Escape return to the same dates and audience. A delayed
  search cannot leak into the URL after the report closes. Removing only that
  cleanup in an isolated browser reproduced the failing regression. Realtime refresh
  pauses while the expanded report is being used.
- Report cards show nine rows and open the full report through View all.
  Mobile cards retain source, page, location, then device order. Previously,
  device cards inherited order zero and jumped ahead of sources. Filtered device
  tabs now fit 320px screens; longer labels reproduced horizontal overflow.
- Measured layout refinements cover container widths, 20px report gaps, overview
  sizing, six desktop/two mobile metric columns, metric typography, 32px rows,
  16px icons, 880px expanded reports, comparison controls, and a sticky toolbar.
  Owlytics keeps its owl, purple accent, light/dark palette, and local icons.

The public tracker remains exactly 6,180 bytes (2,412 bytes gzip). Dashboard JS
increases from 8,933 to 9,189 bytes gzip. No runtime dependencies, storage schema,
visitor hashing, collection behavior, or aggregation cache limits change. Tables
remain paginated rather than accumulating an unbounded client-side row list.

### Remaining differences

## Calendar workflow pass

The live Plausible reference was inspected again on 2026-10-29, including
historical ranges, reopening custom dates, and the date/comparison menus.

- Primary and comparison dates now use a 288 × 312px calendar with month/year
  controls, Sunday-first weekdays, six date rows, a today marker, hover previews,
  and two-click submission. Reversed clicks sort into an inclusive range.
- Applied custom dates reopen in their month with the saved range highlighted.
  Dismissing an unfinished range restores the applied dates. Preset ranges start
  with an unselected calendar, matching the reference.
- Bounds come from the site's earliest native/imported history and its reporting
  timezone's current day. UTC calendar arithmetic preserves chosen dates across
  browser timezones, DST, leap days, and year boundaries. The existing 3,660-day
  server limit remains enforced; no future dates can be selected.
- Date presets show shortcut hints and reference-style grouping. Disable comparison
  is available in the primary date menu, and comparison choices follow the
  reference order. Owlytics retains its additional 30-day and six-month presets.
- Preset menus could extend below a 390 × 844px screen when comparison controls
  wrapped. The regression reproduced this overflow; menu height now reserves room
  for the wrapped toolbar and keeps the remaining choices scrollable.
- A year-field blur could replace the day grid between pointerdown and click,
  swallowing the first selection. This was reproduced in Chromium and fixed by
  avoiding a redundant redraw after Enter. The regression checks the retained
  first click, not merely the final URL.
- Deferred disclosure initialization could overwrite a year being typed. The
  captured failure combined two year values; calendar initialization now runs
  synchronously before its controls become editable. A regression asserts the
  initial year during the opening click.
- Native GET forms remain usable when JavaScript is disabled. Calendar submission
  uses the existing filter queue and preserves dates, audience, comparison mode,
  metric, import visibility, and the intended interval reset.

The calendar adds no dependency or network request. Dashboard JS is 41,614 bytes
(11,173 gzip); the public tracker remains 6,180 bytes (2,412 gzip). Storage,
visitor/session aggregation, and collection behavior are unchanged.

Validation: formatting, all 203 Rust tests, 17 tracker tests, and 11 general
browser flow groups passed. The final calendar suite passes all four viewport and
timezone combinations, including the year-initialization regression (which fails
against the pre-fix binary), queued filters, and native forms. The report-overlay
regression now waits for document parsing before counting the four background
cards; previously it could observe only three while the response was still loading.
Full dashboard-suite and deployment verification are reported separately.
